Featured · Medical ML · Minor Project 2026

Heart Disease Prediction Using Ensemble Machine Learning with Web Deployment

Cardiovascular disease causes roughly 18 million deaths a year, and linear risk scores such as Framingham miss non-linear and interaction effects. This builds a full ML framework on the public cardio_train dataset (68,530 cleaned records) and delivers it as a patient-facing risk tool with lifestyle recommendations across six clinical domains.

How it works

  • PipelineRobustScaler + OneHot
  • FeaturesAge · BMI · Pulse pressure
  • Base modelsMLP · GB · HGB · RF · Ada · LR
  • CombinationSoft voting
  • ServingFlask REST API + JS

Ensemble results

  • Accuracy74.12%
  • Precision76.46%
  • Recall68.91%
  • F1 · Specificity72.49% · 79.21%
  • AUC-ROC0.812

Approach

Why the details matter

A model that scores well is only half the job. The other half is knowing when to trust it.

Features that make clinical sense

Instead of raw columns I derived BMI, age in years and pulse pressure — variables a clinician would recognise — and checked with mutual information that they added signal.

Explain it at three levels

Global importances say what matters; partial dependence shows where risk turns up; interaction surfaces show how factors combine. Together they check the model against known cardiology.

Choose the metric that fits the harm

The ensemble has the highest precision of all six models, keeping false alarms down — and I report the 31% false-negative rate plainly because that matters for screening.

Ship it, then use it

The model sits behind a Flask API with a responsive front end, sub-second inference and personalised recommendations. Deploying exposes problems a notebook never will.
