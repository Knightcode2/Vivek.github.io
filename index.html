Featured · Medical ML · Minor Project 2026

Heart Disease Prediction Using Ensemble Machine Learning with Web Deployment

Cardiovascular disease causes roughly 18 million deaths a year, and linear risk scores such as Framingham miss non-linear and interaction effects between risk factors. This project builds a full ML framework on the public cardio_train dataset (68,530 cleaned records, near-balanced classes) and delivers it as a patient-facing risk assessment tool with lifestyle recommendations across six clinical domains.

How it works

  • Unified scikit-learn PipelineRobustScaler + OneHot
  • Engineered featuresAge (yrs) · BMI · Pulse pressure
  • Base modelsMLP · GB · HGB · RF · AdaBoost · LR
  • CombinationSoft-voting (probabilities)
  • ServingFlask REST API + HTML/CSS/JS

Soft-voting ensemble results

  • Accuracy74.12%
  • Precision76.46%
  • Recall68.91%
  • F1-score72.49%
  • Specificity79.21%
  • AUC-ROC0.812

Approach

Why the details matter

A model that scores well is only half the job. The other half is knowing when to trust it.

Features that make clinical sense

Instead of feeding raw columns, I derived BMI, age in years and pulse pressure — variables a clinician would recognise — and checked with Mutual Information that they added real signal.

Explain it at three levels

Global importances say what matters; partial dependence shows where risk turns up; interaction surfaces show how factors combine. Together they check the model against known cardiology, not just a metric.

Choose the metric that fits the harm

The ensemble has the highest precision of all six models, keeping false alarms down — and I report the 31% false-negative rate plainly because that is what matters for screening.

Ship it, then use it

The model sits behind a Flask API with a responsive front end, sub-second inference and personalised recommendations. Deploying exposes problems a notebook never will.
